# Rune Cloud Client

Rune Cloud Client is a simple, experimental web-based client for [Rune Cloud](https://github.com/VectorPanic/rune-cloud). It provides a graphical interface for developers to manage games and screensavers through the Rune Cloud API.

The client is written in HTML, CSS, and vanilla JavaScript. It is an early-stage project and is not intended to be a complete administration interface for Rune Cloud.

## Status

**Experimental.** Features, API integration, and the user interface may change. The client is developed alongside Rune Cloud and may not be compatible with every API version.

## Features

- Sign in with a Rune Cloud developer token.
- View and create games and screensavers associated with a developer account.
- Edit game metadata, including descriptions, player settings, input methods, and weighted tags.
- Manage versions and upload JavaScript files and PNG game icons.
- Publish versions through the Rune Cloud API.
- Clear an owned game's global highscores, for example during testing.

Not all Rune Cloud functionality is available through the client.

### Content identifiers

When creating a game, enter the exact application ID from the Rune SDK configuration: the `developer` and `app` values joined by a dot. For example, `developer: "com.vectorpanic"` and `app: "demo"` produce `com.vectorpanic.demo`. The ID is permanent and limited to 100 characters. Its first segment contains two or three lowercase letters; the developer name contains 1–50 lowercase letters, digits or hyphens; the app name contains letters, digits, underscores or hyphens. The app name may contain uppercase letters, and the complete ID must match the game's configuration exactly. Rune Cloud does not allow two game IDs that differ only in letter case.

Screensavers use a separate identifier format: start with a lowercase letter, followed by lowercase letters, digits or hyphens, up to 100 characters.

## Requirements

- A running [Rune Cloud](https://github.com/VectorPanic/rune-cloud) installation.
- A web server that serves static files.
- A browser with JavaScript enabled.
- A Rune Cloud developer token.
- Node.js and npm to rebuild the JavaScript bundle.

## Installation

Clone the repository:

```sh
git clone https://github.com/VectorPanic/rune-cloud-client.git
cd rune-cloud-client
```

Configure your web server to serve the `bin/` directory. The client communicates with an existing Rune Cloud API; it does not include the server or database.

### API configuration

Set the API base URL in `src/system/Config.js`:

```javascript
this.apiBaseUrl = "/api/v1/";
```

The default assumes that the API is available at `/api/v1/` on the same origin. Alternatively, specify an absolute URL ending in `/v1/`, including the trailing slash.

If the client and API use different origins, the Rune Cloud server must allow the client's origin through its CORS configuration.

After changing the JavaScript source or configuration, rebuild the bundle before using the changes in `bin/`.

## Building

The project uses Google Closure Compiler with ES5 output and simple optimizations. From the repository root, run:

```sh
bash scripts/shell/build.sh
```

The script compiles the source files in `src/` into:

```text
bin/src/js/runeclient.js
```

The script can also be invoked from another working directory using its path. The `bin/index.html` file is maintained directly; it is not generated by the build script.

## Project structure

```text
bin/             Static web client and compiled JavaScript
src/             JavaScript source code
scripts/shell/   Build script
```

## Security

The client uses a developer token to authenticate requests to Rune Cloud. The token is sent in the `Authorization` header and stored in the browser's `sessionStorage` during the session. Use HTTPS for deployments and do not expose developer tokens publicly. Access control must be enforced by the Rune Cloud API.
